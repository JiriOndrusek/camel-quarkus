The extension turns document ingestion into configuration. Declare a knowledge base (an _ingestion
pipeline_) and point it at a folder:

[source,properties]
----
quarkus.camel.ai.ingest.products.source.type=file
quarkus.camel.ai.ingest.products.source.directory=/data/docs
quarkus.camel.ai.ingest.products.mode=sync
----

Every file found is parsed, split into segments, embedded with the application's `EmbeddingModel`
bean and written to its `EmbeddingStore` bean. When more than one store or model bean exists,
select them explicitly per pipeline:

[source,properties]
----
quarkus.camel.ai.ingest.products.embedding-store=products
quarkus.camel.ai.ingest.products.embedding-model=my-model
----

=== Staying correct: `mode=sync`

With `mode=sync` the knowledge base *mirrors* its source: an edited document replaces its
previous vectors instead of joining them, a document that shrank loses its stale segments, and an
unchanged corpus costs nothing on restart — change detection uses a cheap fingerprint first
(file size + modification time) and a content hash second, so unchanged documents are skipped
without splitting or embedding.

Sync mode records what was ingested in a small ledger table (`cq_ingest_ledger`) in the
application's datasource. In dev and test mode, Dev Services provides the database
automatically; in production configure `quarkus.datasource.*` as usual, or point the ledger at a
named datasource:

[source,properties]
----
quarkus.camel.ai.ingest.products.ledger.datasource=my-datasource
----

Segment identifiers are deterministic, so on stores whose write overwrites by id (pgvector,
qdrant, elasticsearch) replacement is a plain upsert. Stores that keep or mix old content on
same-id writes (chroma, milvus, the in-memory store) need:

[source,properties]
----
quarkus.camel.ai.ingest.products.write-strategy=remove-then-add
----

Declare the embedding model's identity so a provider-side model change can be detected — bump it
to force re-embedding:

[source,properties]
----
quarkus.camel.ai.ingest.products.embedding-model-id=openai/text-embedding-3-small@2024-01
----

`mode=append` remains available for disposable stores and demos: documents are only ever added,
a restart re-ingests the corpus, and no datasource is needed.

=== Pushing documents from code or routes

Documents can be pushed through the `direct:ingest-<pipeline>` endpoint. The
`CamelAiIngestDocumentId` header is required — replacement and (future) deletion are built on
stable document ids; the optional `CamelAiIngestFingerprint` header enables cheap change
detection for pushed documents:

[source,java]
----
producerTemplate.requestBodyAndHeader("direct:ingest-products", text,
        IngestHeaders.DOCUMENT_ID, "manuals/warranty.pdf", IngestResult.class);
----

[IMPORTANT]
====
This extension is a *preview*. Deletion (a document removed from the source disappearing from
the knowledge base, and an explicit delete/pin API) arrives in a later release, together with
its safety interlocks.
====
