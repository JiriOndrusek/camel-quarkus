## Issue summary
The camel-pqc extension has been promoted from JVM-only to native support and includes basic GraalVM registrations in PqcProcessor, but may be missing cipher transformation registration and explicit algorithm instantiation patterns used by other crypto extensions.

## Relevant files
- `extensions/pqc/deployment/src/main/java/org/apache/camel/quarkus/component/pqc/deployment/PqcProcessor.java` - deployment processor with current native build steps
- `extensions/pqc/runtime/pom.xml` - shows dependency on camel-quarkus-support-bouncycastle
- `extensions/pqc/pom.xml` - parent pom still references extensions-jvm (needs update)
- `integration-tests/pqc/src/main/java/org/apache/camel/quarkus/component/pqc/it/PqcResource.java` - shows PQC operations used (sign/verify, KEM encapsulation)
- `integration-tests/pqc/src/test/java/org/apache/camel/quarkus/component/pqc/it/PqcTest.java` - tests currently disabled due to BC 1.83 compatibility issues
- `extensions-support/bouncycastle/deployment/src/main/java/org/apache/camel/quarkus/support/bouncycastle/deployment/BouncyCastleSupportProcessor.java` - reference pattern for BC provider registration
- `extensions-support/bouncycastle/runtime/src/main/java/org/apache/camel/quarkus/support/bouncycastle/BouncyCastleRecorder.java` - shows explicit cipher instantiation pattern
- `extensions-support/bouncycastle/deployment/src/main/java/org/apache/camel/quarkus/support/bouncycastle/deployment/CipherTransformationBuildItem.java` - build item for registering cipher transformations

## Key observations
- **PqcProcessor already has substantial native registrations**: index-based reflection for all `org.bouncycastle.pqc.*` classes, runtime initialization of BouncyCastlePQCProvider, and standard JCA classes
- **Extension structure is correct**: properly promoted to `extensions/` directory with deployment and runtime modules, though parent pom.xml still references `extensions-jvm` parent
- **Depends on camel-quarkus-support-bouncycastle**: inherits BC provider infrastructure but uses separate BouncyCastlePQCProvider
- **Tests are disabled**: all integration tests have `@Disabled` annotation citing "BouncyCastle 1.83 algorithm naming and header compatibility issues"
- **No service loader files**: camel-pqc uses direct provider registration, not META-INF/services
- **Missing patterns from other crypto extensions**: doesn't produce CipherTransformationBuildItem or use a Recorder for explicit algorithm instantiation

## Answers to research questions

**1. What reflection is needed?**
Already registered via index-based discovery in PqcProcessor:43-55. Covers all classes in:
- `org.bouncycastle.pqc.jcajce.provider.*` (provider implementations)
- `org.bouncycastle.pqc.jcajce.spec.*` (parameter specs: DilithiumParameterSpec, FalconParameterSpec, KyberParameterSpec, SPHINCSPlusParameterSpec)
- `org.bouncycastle.pqc.crypto.*` (crypto implementations)
- `org.bouncycastle.jcajce.spec.KEM` (KEM specs)
- Standard JCA classes: KeyPairGenerator, Signature, KeyFactory, KeyGenerator, SecretKey

**2. What resources must be included?**
None required - no META-INF/services files found for camel-pqc. Provider is registered programmatically via `Security.addProvider(new BouncyCastlePQCProvider())`.

**3. Are there JCA/JCE service providers that need explicit registration?**
No ServiceProviderBuildItem needed. The BouncyCastlePQCProvider is runtime-initialized (line 70-72) and registered programmatically, not via service loader.

**4. Does pqc use dynamic proxies?**
No evidence of dynamic proxy usage in the test code or component structure.

**5. What BouncyCastle classes need ReflectiveClassBuildItem registration?**
All PQC-related classes are already registered through the index-based approach. The pattern-matching filter captures all necessary crypto provider, spec, and implementation classes.

**6. Are there any JNI or native library dependencies?**
None identified - pure Java implementation via BouncyCastle PQC library.

**Additional findings:**
- **Missing CipherTransformationBuildItem production**: Other crypto extensions (crypto-pgp) produce this build item to feed cipher transformations to BouncyCastleSupportProcessor for explicit instantiation
- **No Recorder for explicit algorithm instantiation**: BouncyCastleRecorder pattern (instantiating Cipher.getInstance() at STATIC_INIT) would signal GraalVM about reachable security services, but PqcProcessor doesn't have this
- **Parent pom issue**: `extensions/pqc/pom.xml:24` still references `camel-quarkus-extensions-jvm` parent instead of `camel-quarkus-extensions`
- **Tests are blocked**: Current blocker is BouncyCastle 1.83 algorithm naming compatibility with Camel PQC component, not native compilation issues
