# Research Brief: PQC Extension Native Test Failure

## Summary
The PQC (Post-Quantum Cryptography) extension passes all 6 tests in JVM mode but fails 3 tests in native mode. The root cause is that the Bouncy Castle Post-Quantum Cryptography (BCPQC) security provider is not registered at GraalVM build time, causing `SecurityException` errors when the native image attempts to use KYBER key encapsulation algorithms at runtime.

## Problem Type
**Native compilation configuration issue** - GraalVM security provider registration

## Focus Areas
1. `extensions/pqc/deployment/src/main/java/.../PqcProcessor.java` - needs additional `@BuildStep` for provider registration
2. Similar extensions that register security providers (check other extensions using Bouncy Castle or custom security providers)
3. The BCPQC library dependencies and what other reflective access/resources might be needed

## Key Questions for Researcher
1. What is the correct `@BuildStep` pattern to register the "BCPQC version 1.83" security provider for GraalVM native images in Quarkus?
2. Are there other Camel Quarkus extensions that register Bouncy Castle providers? What's the established pattern?
3. Beyond provider registration, does BCPQC require additional native image configuration (reflection, resources, proxies, etc.)?
4. Should the provider registration be conditional or always included when the extension is present?

**Error context**: Failed endpoints use `KYBER` algorithm with `AES` and `CHACHA7539` symmetric encryption, all requiring the BCPQC provider at runtime.
